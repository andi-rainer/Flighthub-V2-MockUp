# FlightHub V2: Projektdokumentation

Stand: 09.11.2026. Zweck: Wer mit Andreas weiterarbeitet (Claude, andere Agenten, Menschen), findet hier, **was V1 kann, was V2 sicher kann und was offen ist**, ohne dass etwas angenommen werden muss.

## Statuslegende

Jede Aussage trägt ihren Status. Nur was als beschlossen gekennzeichnet ist, gilt für V2.

| Marke | Bedeutung | Gilt als Vorgabe? |
|---|---|---|
| `[N dd.mm.]` | Andreas hat es gesagt oder entschieden (Datum der Nachricht in der Sitzung 06.–09.11.2026) | **ja** |
| `[akzeptiert]` | Vorschlag von Claude, von Andreas pauschal angenommen („Der Rest ist alles super und gute Vorschläge“, 06.11.); Details nicht ausgearbeitet | Richtung ja, Details nein |
| `[N, im Dummy umgesetzt]` | Wunsch von Andreas, die genaue Form im Dummy ist Entwurf | Wunsch ja, Form nein |
| `[V1]` | Tatsache über V1 (aus der V1-Projektdokumentation oder der Code-Inventur vom 06.11.2026) | Faktum |
| `[C]` | Claude-Entwurf im Klickdummy, nicht ausdrücklich bestätigt | **nein** |
| `[Vorschlag]` | Idee, noch nicht entschieden | **nein** |
| `[Offen]` | Frage, die entschieden werden muss | **nein** |
| `[Recherche]` | Fund aus dem Internet, ungeprüft | **nein** |

## Pflege

- Neue Entscheidung von Andreas → in 02 mit Datum eintragen, aus 04 entfernen, bei Dummy-Auswirkung 03 anpassen.
- Neue Idee oder Frage → nur in 04, mit Marke.
- Der Wortlaut der Nachrichten von Andreas liegt nicht im Repository (das Repository ist öffentlich); Datumsmarken verweisen auf die Sitzung vom 06. bis 09.11.2026.
